PAX root qualification prediction (2026-11-12)

Baseline: 816d457985535a32247f73ff0478448868c5d1a8; PAX baseline
0e2843cff2bd8712317190bb02c632e87cd29bb9. Inputs include the design and
comparison matrix, format/trust/transaction specifications, earlier test
records, transaction adapters, image pins, installed inventory and journal
documentation. This prediction preceded the census implementation.

Before enabling mutations, measure an installer-created QEMU root, not an
initramfs or a tools/mkdisk journalled playground substituted for it. Predict
plain ext2, no active journal. statfs magic 0xef53 is insufficient; PAX does
not document Linux's /proc/fs/jbd2 device qualification. Keep mutations refused.
The root '/' refusal remains until a separately qualified maintenance/rescue
entry exists. Raw ABI success does not authorize live-root writes.

Measure: root mount identity and ext superblock features, statfs/fstatfs,
openat O_DIRECTORY/O_NOFOLLOW at each ancestor, exclusive file creation,
file and directory fsync, renameat identity/replacement, fchownat no-follow,
fchmod/fchown, mkdirat/symlinkat/linkat/readlinkat/newfstatat/unlinkat/getdents,
flock contention and release, cwd pinning. Successful sync is syscall evidence,
not a power-cut claim. Compare with Linux using the same probe binary.

Predict the existing parser/version/solver rows remain portable, but the Python
guest runner and Linux /proc/fs/jbd2 qualification do not run unchanged on PAX.
None of the mutation/config/crash rows is a passing PAX transaction merely
because individual ABI probes pass. The NBD recorder can stay on the Linux QEMU
host; the Linux cloud-init/loop-mount/e2fsck guest driver needs a PAX boot/reboot
driver.

The adoption options are one filtered base package, per-tool exact-inventory
adoption with the residual base retained by pax-upgrade, or a disjoint prefix.
Per-tool adoption is selected: both writers enforce disjoint ownership, with
exact trusted image hashes/types/modes/owners/link topology, no payload rewrite,
and refusal on local changes. Boot/kernel/passwords/homes remain image-owned or
user-owned. A full image inventory cannot be imported as F5: boot/var paths and
set-ID bits are prohibited, and generated files differ per installation.

The image integration will build the package manager from a pinned source tree,
as it builds the other Wolf tools. An earlier binary-only input proposal is
superseded. Machine-specific input paths and evidence stay outside the source
tree. The census accepts its image directory and output directory explicitly.

A separately qualified journalled fresh install is selected if the census
confirms plain ext2; no in-place conversion and no weakening of refusal. A
maintenance boot entry must run before login and the SSH server, with a trusted
rescue copy outside package-replaced paths and shared exclusion for both writers.
Those system changes are separate prerequisites, not implied by this census.

A capability lie must make a named refusal row fail in a separate test branch.
No real signing key, running installed machine or network deployment is used.
