== 1. On-disk layout (ROOT is the synthetic root, never the host /)

ROOT/var/lib/<former-name>/            0700, the root-owned state (one filesystem with ROOT)
  lock                          persistent lock inode, 0600, made once by init,
                                never unlinked or recreated; no PID inside
  current                       the commit decision: current { schema, features,
                                generation, database (sha256 of db.lrd), transaction }
  generations/<N>/db.lrd        immutable generation N: arch, slot, repository,
                                ownership mode, packages [name, version, arch, slot,
                                reason explicit|dependency, manifest sha256, config
                                baselines], residuals, proposals, accounts, pending
                                actions. 24 packages at most (F3 snapshot-limit).
  objects/sha256/<hex>          immutable verified manifests the generations name;
                                derived ownership index is rebuilt from them
  transactions/t<N>/            the one in-flight transaction to generation N
    intent                      framed line format, whole-file SHA-256 trailer
    backup/<i>                  durable preimage copies of op i
    stage/<package>/            pm02 stage output (validated, digest-verified)
  trust/                        pm03 trust generations (monotonic, outside rollback)
ROOT/var/cache/<former-name>/          pm03 hash-bound cache (.part, objects/sha256)

Generation numbers and transaction ids are deterministic (t<N> makes N), so two
identical runs give identical bytes; an undone transaction removes its
uncommitted generations/<N> so the number is reused.

Commit authority is current alone: current naming t<N>'s generation
means finish; anything else means undo. No COMMITTED record contradicts it.
Rescue (section 6) is itself a sequence of idempotent durable steps, each with
its failpoint: rescue:undo:<i>:temp, rescue:undo:<i>, rescue:generation,
rescue:finish:<k>, rescue:done.
Cache actions are planned, recorded as pending after C and never executed. Account and directory actions are ordinary ops inside A
(etc/passwd, etc/group, etc/shadow when present: whole-file replace with backup).

== 3. Ownership, config and removal rules

- Ownership index: path -> package, from the current generation's manifests.
  Install refuses file-conflict (another owner not removed by this plan),
  unowned-collision (an existing unowned non-directory), directory-conflict
  (co-owned directory with different mode/owner/group). No --overwrite.
- Config three-way for each configs path: B baseline (packaged digest in the old
  generation), L live digest or absent, N new packaged digest.
  L absent: stays absent (baseline becomes N). L == B: install N.
  L != B, N == B: keep L. L != B, N != B: keep L; if L != N write
  PATH.<former-name>-new = N, an owned proposal; an unowned PATH.<former-name>-new refuses
  proposal-exists. Fresh install over an existing path: unowned-collision.
- Removal deletes owned paths whose live identity equals the recorded one; a
  modified owned file (config or not) stays as a recorded residual; a directory
  goes only when empty and its last owner leaves; --purge deletes the residual
  configs it lists, nothing else. Accounts are never deleted (residual account).
- Upgrade replaces a modified non-config owned file (its preimage is backed up
  until C) and reports it; configs use the three-way rule.
- Reasons: explicit for named packages, dependency otherwise. autoremove computes
  packages unreachable from explicit roots over required edges (provides
  included), cycles collected together; without --yes it previews, no writes.
  remove of a package something else requires refuses required-by, naming them.
- Whole-snapshot upgrade: upgrade resolves every explicit package
  against the trusted targets and installs the latest compatible closure.

== 5. The check: "old or new consistent generation only, recovered twice identically"

digest(ROOT) = SHA-256 over every entry under ROOT in byte order of path:
path, type, mode, uid, gid, length, content SHA-256 or link target, and hardlink
class (the first path of each inode). Excluded, by name: var/lib/<former-name>/trust/
and var/cache/<former-name>/ (trust is monotonic outside package rollback),
and every time field. Nothing else is excluded: current, generations,
objects, transactions and every temp name are inside the digest.
REF_OLD = digest of a root that never ran the transaction (same fixture).
REF_NEW = digest of a root where the same transaction ran to completion.
For a cut state S: R1 = digest after `rescue`, R2 = digest after a second
`rescue`. PASS iff exit codes are 0, R1 == R2, R1 in {REF_OLD, REF_NEW},
R1 == REF_OLD for every cut before C's rename is visible and REF_NEW for every
cut after it, `verify` passes, no t<N> or .<former-name>-t<N>-* name remains, and a
sentinel tree outside ROOT is byte-identical. A process cut at commit-renamed is
REF_NEW; a power cut at the same step may be either, never anything else.
Before rescue, status says recovery-needed and install/remove/upgrade exit 8.

== 6. Rescue entry

`lrd rescue --root DIR` takes the lock, reads current and transactions/.
committed t<N>: verify the live plan equals generation N, finish (F).
uncommitted t<N> with a valid intent: undo in reverse op order (A's rule),
remove generations/<N>, verify against current, remove t<N>.
t<N> without a valid intent: nothing live was touched; remove t<N>.
Nothing pending: "rescue: nothing to do", exit 0, zero writes.
Refusals, exit 9, zero further writes, each by name: rescue-unknown-state PATH
(live identity is neither old, new nor our temp), rescue-missing-backup,
rescue-malformed-intent, rescue-ambiguous-generation (current names a missing or
invalid generation), rescue-foreign-temp. A refused rescue is repeatable: once
the operator restores the named path, rescue proceeds.

== 8. Power cuts (QEMU, journalled guest)

Guest: Ubuntu 24.04 cloud image (kernel, initrd, rootfs), each a digest-checked
staged input in a staging directory on the primary Linux host, downloaded outside the locks. KVM on
the primary Linux host (/dev/kvm present, 70 GB free at 01:12Z). The data disk is ext4
(mkfs.ext4, journal, metadata_csum) served to QEMU by a recorder written from
the NBD protocol specification: it logs every WRITE (offset, bytes), FLUSH and
FUA in arrival order, plus a marker export the package manager's test binary writes after
each durable step. Crash states are synthesized offline: for every FLUSH
boundary k, the prefix through k (the cut just after a barrier), the prefix
plus all writes before k+1 (the cut just before the next), and seeded subsets
of the in-flight writes with 512-byte sector tearing. A second guest boot
loop-mounts each state (ext4 replays its journal; mounted noauto_da_alloc so
ext4's rename heuristic cannot hide a missing fsync), runs rescue twice and
reports section 5's digests over virtio-serial. Unix socket paths stay under
108 bytes. Real ENOSPC on a small ext4; real EIO by QEMU blkdebug on the data
disk; plain ext2 refused by qualification. Predicted: every state recovers to
REF_OLD or REF_NEW; before C's barrier always REF_OLD.
